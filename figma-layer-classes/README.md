# Спецификация скилла `figma-layer-classes`

## Назначение

`figma-layer-classes` помогает переносить имена слоёв из Figma в CSS-классы без переименования и незаметных пропусков. Он нужен при локальной вёрстке отдельных блоков, компонентов и целых сайтов по макету.

Исполняемые инструкции находятся в [SKILL.md](./SKILL.md). Этот документ описывает назначение скилла, его область применения и ожидаемый результат.

## Когда применять

Используйте скилл, когда код создаётся или проверяется по Figma и важно, чтобы имена слоёв совпадали с классами в HTML/JSX и CSS.

Скилл работает с локальным веб-кодом в HTML и JSX. Он не заменяет процесс реализации дизайна по Figma и не является отдельным автоматическим линтером.

## Основное правило

Имя соответствующего слоя Figma — источник точного имени CSS-класса. Сохраняются регистр, написание, пунктуация и длина. CSS-селектор при необходимости экранируется; такое экранирование не меняет значение класса в разметке.

Не добавляются собственные, БЭМ-, utility-, CSS Modules-, генерируемые и state-классы. Если поведение требует хука, для него используются `data-*`, ID или селектор элемента.

## Рабочий процесс

1. Получить структуру выбранного узла через Figma MCP. При вызове `get_design_context` сначала выполнить требования обязательного скилла `figma-design-to-code`.
2. Зафиксировать имена, типы и пути или ID всех слоёв в заданной области: выбранного блока либо всех реализуемых секций сайта.
3. Сопоставить каждый видимый или интерактивный элемент с соответствующим слоем и назначить его точное имя классом. Видимые текстовые слои также учитываются.
4. Пропустить слой можно только тогда, когда он чисто технический и не представляет отдельный отображаемый или интерактивный элемент. Причину нужно записать в аудите.
5. Сверить соответствия в обе стороны: Figma → разметка и разметка → Figma. Затем проверить, что CSS-классы существуют в разметке.
6. Исправить найденные несовпадения и составить итоговый отчёт.

## Ограничения и обработка проблем

- Пробелы в имени разделяют HTML class-токены. Такое имя нельзя заменять дефисами, разбивать на несколько классов или считать точным соответствием. Отметить блокировку и запросить разрешение имени в Figma либо отдельное решение пользователя.
- Если Figma MCP недоступен, скриншот или существующий код не подтверждают список имён. Нужен доступ к структуре либо предоставленный пользователем полный список слоёв.
- Для динамического `className` проверяются все возможные значения. Неизвестные значения отмечаются как непроверенные.
- Явно разрешённое пользователем переименование фиксируется как исключение. Оно не считается точным совпадением и не позволяет объявить аудит точных имён завершённым.
- Независимые подтверждённые части можно продолжать, но нельзя выдавать неполный аудит за полный.

## Формат результата

В ответе и в файле `figma-class-audit.md`, сохранённом рядом с реализацией, указываются:

- область проверки и исходный узел Figma;
- таблица «слой Figma → DOM-элемент/класс → статус»;
- технические пропуски и причины;
- исправленные несовпадения;
- блокировки и непроверенные значения.

Для целого сайта используется один сводный отчёт. Статус «проверка завершена» допустим, только если каждому классу соответствует точное имя слоя либо задокументирован технический пропуск, а блокировок, исключений и непроверенных значений нет.

## Установка

В корне репозитория выполните `./install.sh` на macOS/Linux или `./install.ps1` в PowerShell. Скрипты копируют папки скиллов в личный каталог Codex. После установки или обновления перезапустите Codex.
